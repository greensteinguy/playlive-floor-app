# iPad Pass Report — Phase 5.4 (code-level audit)

**Date:** 10 August 2026
**Scope:** every operator screen (`src/pages/**`), shared components, shell, global CSS/viewport config — audited for touch-only iPad (Safari) usability. Tap-target sizes computed from Tailwind classes against the 44pt iOS HIG minimum.
**What this is / isn't:** the code-level half of task 5.4. The on-device half — feel, performance on older iPads, Safari quirks in anger — happens on Guy's venue iPad against staging (pairs naturally with the team-testing round now starting).

**Bottom line:** the app's *architecture* is already touch-first — zero drag-and-drop, zero double-click, zero mouse-only or right-click handlers anywhere; seat moves use tap-to-pick-up/tap-to-drop; reordering uses ▲/▼ buttons; nearly every table scrolls horizontally; money/number inputs get the right iOS keyboards; the clock controls and login are exemplary. The problems are concentrated in **tap-target sizing** on a handful of dense screens — worst exactly where the money and player-state actions live.

**Fixed this session (see commit):** all four blockers + the mechanical majors (B1–B4, M5, M7, M8, M9). Remaining items are listed with suggested fixes; several Tables.jsx ones should fold into the pending floor-staff seating UX walkthrough rather than being polished twice.

## MAJOR — open (needs UX judgment, not just classes)

- **M1. Disabled-button reasons live in `title` tooltips** (`Tables.jsx` — Close/Seat-next/Record-draw). iPad never shows `title`; the operator sees a dead button with no explanation. Fix: render the reason as visible helper text. *Fold into the seating walkthrough.*
- **M2. Seat-pip occupant names are hover-only** in the collapsed room overview (mitigated by "Show seats"/"Expand all"). Options: default-expand on coarse pointers, or initial-in-pip. *Seating walkthrough.*
- **M3. `Tables.jsx` unpadded 10px text-buttons** ("Show seats", "Expand all", "Seat next →", CSV) — add `px-3 py-2 -my-2` hit-box padding. *Seating walkthrough.*
- **M4. PlayerPicker nested scroll** — 288px inner scroller, invisible iOS scrollbar, no `overscroll-contain`, no "showing N of M" affordance. Small fix but touches the shared desk control — do with a desk-flow retest.
- **M6. `autoFocus` pops the keyboard over the content** (`Players.jsx`, `PlayerPicker.jsx`, `TournamentRegister.jsx`, and worst: the void-reason input inside a table row). Fix: gate on `(pointer: coarse)`. Deliberately deferred — changes desktop behaviour too; decide once with Guy.
- **M10. `Tables.jsx` inline word-buttons** "unseat · eliminate · milestone reached" — opposite outcomes one mis-tap apart in a running sentence. Promote to chip buttons. *Seating walkthrough.*

## MINOR — open (polish)

- N1: `min-h-screen` = `100vh` on standalone pages (Login/Forbidden/loading) — bottom ~60px under iOS Safari's toolbar until scroll; use `100dvh`.
- N2/N3: Toast dismiss × unpadded; bottom-fixed toasts sit under the Safari toolbar — `bottom-[max(1rem,env(safe-area-inset-bottom))]`.
- N4: `viewport-fit=cover` is set but no `env(safe-area-inset-*)` used anywhere — add bottom inset padding to `#root` if Home-Screen install is a real use case.
- N5: steppers (`Tables.jsx` seats stepper, `SessionPlanBuilder`) narrow — `w-11 h-11`.
- N6: admin date/selects ~26px tall (AuditLog, Reconciliation, Dedupe) — low priority, admin screens.
- N7: bounty-value remove × overlaps its own input (`FormFields.jsx`) — move outside, pad.
- N8: truncated values (withdrawal requester/reference, audit summaries) readable only via `title` — surface in expanded rows.
- N9: clock session-picker chips ~30px — once-per-session action, lowest priority.

## Already right (keep doing this)

Global `touch-action: manipulation` + text-size-adjust; 44px clock controls and login; horizontal scroll containers on effectively every table; whole-row `<label>` wrapping on checkboxes/radios; stretched-link rows; `active:` press feedback throughout; backdrop-tap + explicit Done on modals; fixed pseudo-element background (avoids the iOS `background-attachment: fixed` bug); body-scroll lock on the drawer written for iOS specifically.
